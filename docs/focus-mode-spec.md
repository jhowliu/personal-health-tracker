# 專注練模式 · 開發說明

對照檔案：`focus-mode.html`（可操作的畫面草圖，上方按鈕可直接跳到各個狀態）
技術假設：React Native + Expo。如果是 bare React Native，通知與震動套件需要替換，邏輯相同。

---

## 1. 目標

讓使用者在健身房把手機當「練習中的操作面板」：

- 一個畫面只處理「現在這一組」，每組只需要點一下。
- 休息時間自動倒數，結束時震動提醒，使用者可以離開 App 去滑手機。
- 不強制保持螢幕不熄滅。

不在這次範圍：Live Activity／動態島、超級組（superset）、放棄整次訓練紀錄、編輯已完成的組（見第 9 節）。

---

## 2. 流程與狀態

```
今天頁（開始前）
   │ 開始訓練 / 繼續訓練
   ▼
專注頁 ──────────────┐
  ├─ 練習中（work）   │  完成第 N 組 → 休息中
  ├─ 休息中（rest）   │  休息結束／略過 → 練習中
  └─ 有氧（time）     │  完成這個動作 → 下一個動作
   │ 全部動作完成       │
   ▼                  │  ✕ → 離開確認 → 暫停（回今天頁，可繼續）
訓練總結 ◀────────────┘     或 結束並儲存
```

專注頁是同一個畫面元件，用兩個狀態切換外觀：

| 狀態 | 條件 | 外觀差異 |
|---|---|---|
| 練習中 | `rest === null` | 米色背景、大字「第 N 組」＋組數圓點、主按鈕「完成第 N 組」 |
| 休息中 | `rest !== null` | 背景變淡紫（`#F7E9F0`）、上方顯示倒數圓環、按鈕改為「+30 秒」「略過休息」 |

背景顏色的切換是刻意的，讓使用者放下手機瞄一眼就知道現在是練還是休息。

進入專注頁時隱藏底部分頁列（今天／身形／餐點／訓練／設定），避免誤觸。

---

## 3. 畫面規格

### A. 今天頁（開始前）

- 標題區：「今天的訓練」＋訓練名稱＋「N 個動作 · 約 X 分鐘」。
- 動作清單：只讀的摘要列，每列顯示「名稱」與「3 組 × 10–12 · 50 kg」或「20 分鐘」。已完成的列為淡綠底＋「✓ 完成」。
- 主按鈕：沒有進行中的訓練時顯示「開始訓練」；有進行中的訓練時顯示「繼續訓練 · 2 / 5」。
- 次要文字按鈕：「直接記錄，不用計時」→ 進入原本的清單式記錄畫面。
- 「略過今天訓練」維持前一版設計（右上 ⋯ 選單＋確認）。

### B. 專注頁（共同結構）

由上到下：

1. **頂部列**：左 ✕（離開）、中「訓練時間 mm:ss」、右「目前動作 / 總數」按鈕（點開動作清單）。
2. **分段進度條**：每個動作一段，完成＝綠、目前＝紫、未做＝灰。
3. **內容區**（可捲動）：動作名稱（30pt）、目標、主視覺、數值調整、已完成組紀錄。
4. **底部操作區**：固定在底部，主按鈕高 64pt。

### C. 專注頁 · 練習中（重量訓練）

- 主視覺：大字「第 2 / 3 組」＋三顆圓點（完成＝綠實心、目前＝紫框、未做＝灰框）。
- 數值：「重量」步進器（每次 ±2.5 kg）、「次數」步進器（每次 ±1）。按鈕 60×56pt，數字 38pt。
- 預設值：帶上次這個動作最後一組的重量與次數，並在上方小字寫「上次 45 kg × 12，已帶入」。第一次做這個動作則帶課表數字。
- 已完成組：以綠色小膠囊顯示「✓ 第 1 組 45 × 12」。
- 提示行：最後一組時顯示「做完這組，下一個：坐姿滑輪划船」；今天最後一組顯示「這是今天最後一組」。
- 主按鈕：「完成第 N 組」；今天最後一組為「完成最後一組」。

### D. 專注頁 · 休息中

- 頂部多一行紫色小字：同動作下一組顯示「下一組 · 第 2 / 3 組」；換動作顯示「下一個動作」。內容區顯示的是**即將要做的**動作與數值，不是剛做完的。
- 主視覺：倒數圓環（直徑 200pt、粗 12pt），中間「休息中」＋剩餘時間（52pt）。圓環隨時間變短。
- 數值步進器維持可操作，讓使用者在休息時就先調好下一組的重量與次數。
- 按鈕：左「+30 秒」（次要）、右「略過休息」（外框主色）。
- 休息結束時自動回到「練習中」，不需要再按一次「開始」。前景時加一次震動與短提示「休息結束，開始下一組」。
- 預設休息 90 秒（之後可做成每個動作可設定，這次先寫死或放在設定）。

### E. 專注頁 · 有氧／計時類動作

- 主視覺：大字倒數（76pt），預設為課表時間（例如 20:00）。
- 次要按鈕：「開始計時」→「暫停」→「繼續計時」。
- 「實際時間」步進器（每次 ±1 分鐘），預設帶課表時間。不計時直接調整也可以。
- 主按鈕：「完成這個動作」。時間到時震動並顯示「時間到」，但不自動完成，由使用者按主按鈕。
- 有氧動作完成後不進入休息，直接換到下一個動作。

### F. 動作清單（底部抽屜）

- 觸發：點頂部右上「2 / 5」。
- 每列：序號與名稱、右側狀態（「✓ 完成」、「目前」、「1 / 3 組」、「未開始」）。
- 點未完成的動作 → 切換到該動作並取消休息。主要情境是器材被占用時先換別的動作做。
- 已完成的動作不可點（見第 9 節）。

### G. 離開確認（底部抽屜）

標題「要離開訓練嗎？」，說明「已完成的組數都已經記下來了。」

- 繼續訓練（主按鈕）
- 暫停並離開，稍後再繼續 → 回今天頁，訓練時間停止計算，今天頁按鈕變成「繼續訓練」
- 結束並儲存（文字按鈕，只有至少完成一組時顯示）→ 進入總結頁

### H. 訓練總結

- 標題「今天練完了」＋「背部 · 5 個動作」。
- 三個數字：訓練時間、完成組數、總量（Σ 重量 × 次數，kg，千分位）。
- 動作列表：名稱＋每組結果（例如 `45 × 12 · 47.5 × 12 · 47.5 × 11`）。破紀錄的動作右側顯示「新紀錄」標籤。
- 主按鈕「完成並儲存」；次要「回去修改」→ 回到專注頁並重新打開最後一組（把最後一筆紀錄移除，讓使用者重填）。

## 4. 資料模型（建議）

```ts
type SetLog = { weightKg: number; reps: number; at: number };   // at = epoch ms

type ExerciseProgress =
  | { kind: 'sets'; exerciseId: string; plannedSets: number; repsRange: string;
      weightKg: number; reps: number;       // 下一組的預設值（步進器目前的值）
      logs: SetLog[] }
  | { kind: 'time'; exerciseId: string; targetMin: number;
      actualMin: number; done: boolean };

type WorkoutSession = {
  id: string;
  date: string;                 // 訓練日（YYYY-MM-DD）
  startedAt: number;            // epoch ms
  pausedAt: number | null;      // 暫停離開時設定，繼續時清除
  pausedTotalMs: number;        // 累計暫停時間
  currentIndex: number;         // 目前動作在 exercises 的位置
  exercises: ExerciseProgress[];
  rest: null | {
    endsAt: number;             // epoch ms，休息結束時間
    totalSec: number;           // 用來畫圓環比例
    notificationId: string;     // 預約的本機通知 id
    nextIsNewExercise: boolean; // 影響「下一組／下一個動作」文字
  };
  finishedAt: number | null;
};
```

衍生值（不要另外存）：

- 訓練時間 = `(pausedAt ?? now) - startedAt - pausedTotalMs`
- 休息剩餘秒數 = `max(0, ceil((rest.endsAt - now) / 1000))`
- 動作是否完成：`sets` → `logs.length >= plannedSets`；`time` → `done`
- 總量 = Σ（`weightKg × reps`）
- 新紀錄 = 該動作任一組的重量 > 歷史最大重量（歷史最大值從過去紀錄查，不存在 session 裡）

持久化：每次完成一組、調整數值、開始／結束休息都立即寫入本機儲存（AsyncStorage／MMKV／SQLite 用你們現有的即可）。App 被系統殺掉後重開，今天頁應該顯示「繼續訓練」。

## 5. 休息倒數與通知

核心原則：**不要用每秒減 1 的計數器當作真實時間**。真實時間只存 `rest.endsAt`，畫面每秒用 `endsAt - Date.now()` 重算。這樣切到別的 App、螢幕鎖定、被背景暫停，回來時數字都是對的。

### 完成一組時

1. 組成 `SetLog` 寫入 `logs`，`currentIndex` 視情況前進。
2. 若還有下一組（或下一個重量訓練動作）：
   - `endsAt = now + totalSec * 1000`
   - 預約本機通知，秒數為 `totalSec`（Expo 的 `scheduleNotificationAsync`，trigger 類型為 `TIME_INTERVAL`）
   - 把回傳的 id 存進 `rest.notificationId`
3. 若已是今天最後一組：不休息，直接進總結頁。
4. 若剛完成的是有氧動作：不休息。

### 通知內容

- 標題：「休息結束」
- 內容：「開始第 3 組」或「下一個：坐姿滑輪划船」
- 聲音與震動：開啟。實際會不會響或震，由使用者的靜音鍵與專注模式決定。

### 「+30 秒」「略過休息」

- 先 `cancelScheduledNotificationAsync(rest.notificationId)`。
- 「+30 秒」：`endsAt += 30000`、`totalSec += 30`，重新預約通知。
- 「略過休息」：`rest = null`，不重新預約。

### 前景、背景與重新開啟

- App 在前景：通知不要跳出（設定通知 handler 為不顯示、不發聲），休息結束時改用 `expo-haptics` 震動一次，並直接切回「練習中」。
- App 在背景或螢幕鎖定：由系統發出預約的通知。
- 使用者點通知或自己切回 App：監聽 `AppState` 變成 `active` 時重新計算 `rest.endsAt`。如果已經過期，直接設 `rest = null`（回到練習中）。
- App 被殺掉：預約的通知仍會由系統發出。重開 App 時從儲存還原 session，再依 `endsAt` 判斷是否仍在休息。

### 權限與頻道

- 第一次按「開始訓練」時請求通知權限（即使只用本機通知也需要）。
- 被拒絕時：專注頁照常運作，改用前景震動與畫面倒數；在專注頁顯示一次性提示「開啟通知後，休息結束會提醒你」，附前往設定的連結。
- Android：先建立通知頻道（重要性設高、啟用震動），並在預約通知時指定該頻道。
- API 細節（trigger 欄位、handler 的設定欄位）會隨 Expo SDK 版本不同，請以專案使用版本的 `expo-notifications` 文件為準。

### 螢幕保持不熄滅

預設**關閉**。可以在設定頁做一個開關，使用 `expo-keep-awake`。專注頁不需要依賴它。

## 6. 互動與邏輯規則

- **步進器**：重量最小 0，每次 ±2.5 kg；次數最小 1，每次 ±1；時間最小 1 分鐘，每次 ±1。長按可連續增減（建議）。
- **預設值來源**：重量與次數＝上次這個動作最後一組；沒有歷史則用課表。調整後的值延續到下一組，不會被重設。
- **下一個動作的選擇**：完成目前動作後，從目前位置往後找第一個未完成的動作，找不到再從頭找。全部完成則進總結頁。
- **跳到其他動作**：從動作清單選擇時，立刻切換並取消休息（同時取消預約的通知）。已完成組數保留。
- **休息時間**：預設 90 秒。換動作時的休息也是 90 秒。
- **完成按鈕防連點**：點擊後 300ms 內忽略第二次點擊，避免重複記錄一組。
- **離開不丟資料**：✕、系統返回手勢、被系統殺掉，都不應該遺失已記錄的組。
- **暫停並離開**：設定 `pausedAt`，取消休息通知（`rest = null`）。繼續時 `pausedTotalMs += now - pausedAt`、清除 `pausedAt`。

## 7. 視覺與無障礙

- **色彩**：沿用現有 App：背景 `#FAF8F5`、主色紫紅 `#A3215B`、淡紫 `#F7E9F0`、完成綠 `#3B7658`、完成淡綠 `#E9F3ED`、淺灰褐 `#EFEBE5`。
- **數字**：所有計時與重量使用等寬數字（tabular nums），避免倒數時寬度跳動。
- **觸控區**：所有可點元素至少 44×44pt。主按鈕 64pt 高、貼近底部，單手拇指可及。
- **狀態不只靠顏色**：休息中除了背景變色，還有圓環與「休息中」文字；完成的組有 ✓。
- **文字縮放**：支援系統字體大小。倒數與主按鈕文字放大時，內容區可捲動，底部操作區仍固定可見。
- **螢幕閱讀器**：步進器的 − / + 要有「減少重量」「增加重量」標籤；倒數圓環要有「休息剩餘 1 分 24 秒」的文字，且不要每秒朗讀（可用較低頻率或僅在使用者聚焦時讀出）。
- **減少動態效果**：系統開啟「減少動態效果」時，圓環與背景改為不做過場動畫。

## 8. 驗收條件

1. 從「開始訓練」到總結頁，一般重量動作每組只需要點一次主按鈕（不需要額外按「開始」）。
2. 休息中把 App 切到背景、螢幕鎖定，時間到時會收到通知（已授權通知、非靜音的前提下）。
3. 休息中切走再回來，倒數剩餘時間與實際時間一致（誤差 1 秒內）。
4. 按「+30 秒」或「略過休息」後，不會收到舊的通知。
5. 在專注頁任意時刻殺掉 App 再重開，今天頁顯示「繼續訓練」，已完成的組都在。
6. 休息時調整重量／次數，結束後「練習中」畫面帶的是調整後的數值。
7. 在動作清單切換到其他動作後，原動作已完成的組不遺失，回來能接著做。
8. 暫停並離開、再繼續，訓練時間不包含暫停期間。
9. 通知權限被拒時，專注頁仍可完整使用，且有一次性提示。
10. 最後一組完成後直接進總結頁；總結頁的組數與總量與實際記錄一致。

## 9. 待確認與後續

- **編輯已完成的組**：目前已完成的動作在清單裡不可跳回，只有總結頁的「回去修改」能重開最後一組。建議第二階段加上「點已完成組的膠囊可修改」。
- **略過這個動作**：目前靠「換動作」處理器材被占用；若要標記「今天不做」需要再定義統計方式。
- **放棄整次訓練**：離開選單沒有「放棄不儲存」，需要產品決定是否提供。
- **休息時間可設定**：例如大重量動作 3 分鐘、輔助動作 60 秒。
- **Live Activity／鎖定畫面倒數**：iOS 可以做，需要原生模組，不在這次範圍。
- **畫面中的數字是示範**：上次紀錄、第 5 個動作「繩索面拉」、訓練名稱「背部」、「約 50 分鐘」都是假資料，請以實際課表資料取代。

## 10. 實作決策（2026-10-02，和上文不同時以本節為準）

- **休息時間**：固定 90 秒，不讀課表的 `rest_sec`。休息中的按鈕是「−30 秒」「+30 秒」「略過休息」（上文只有 +30 秒）。
- **計時類動作**：一律以分鐘處理，儲存時換成 `duration_sec`。即使課表寫「3 組 × 60 秒」，也只按一次「完成這個動作」，記成一筆紀錄。
- **徒手動作**：動作的器材是徒手（`equipment = bodyweight`）時隱藏重量步進器，總量不計入。其他器材即使課表沒寫重量（內建課表都沒寫），也顯示重量步進器，從 0 開始。
- **只有今天能用**：今天頁翻到過去的日期時，沒有專注模式，只能在動作清單裡補記。
- **專注模式裡已完成的不能改**：總結頁拿掉「回去修改」（上文 3-H、第 9 節）；在專注模式和總結頁裡，已完成的組和動作都不能編輯。要改就回今天頁的動作清單（見下方「今天頁的動作清單」）。
- **上次紀錄與新紀錄**：`GET /days/{date}/workout` 的每個動作帶 `last_set`（這一天之前最後一組的重量、次數、時間、回饋）和 `best_weight_kg`（這一天之前的最大重量）。
- **進行中的訓練存在本機**：開始和暫停的時間、休息結束時間、目前動作、步進器的值，用 AsyncStorage 存。組紀錄仍以後端為準，每完成一組就送出。
- **測試**：App 使用 jest-expo；專注模式的狀態邏輯寫成純函式，用單元測試涵蓋驗收條件 3、4、8。
- **回饋**：整個動作做完才問，不是每組都問。在換到下一個動作前的休息畫面顯示「這個動作感覺如何？輕鬆／剛好／吃力」（選填）；當天最後一個動作改在總結頁問；計時類動作不問。回饋存成那個動作最後一組的 `effort`。
- **下次的預設值**：重量用 `suggested_weight_kg`（後端依上次最後一組的重量和回饋計算：輕鬆 +2.5 kg、吃力 −2.5 kg），次數用上次最後一組；第一次做的動作用課表數字。畫面寫「上次 45 kg × 12（輕鬆），建議 47.5 kg，已帶入」。
- **移除「套用到課表」**：下次會自動從上次＋回饋建議開始，回寫課表沒有意義。清單模式的按鈕和 `PUT /workout-templates/{id}/items/{item_id}/weight` 一併移除。
